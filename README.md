## 一、先按学生情况分流

| 学生情况 | 优先检索的岗位 | 需要检查 |
| --- | --- | --- |
| 本科，有开发项目 | AI 应用开发、后端开发（AI 方向）、Agent/RAG 开发、软件开发、测试开发、部署交付 | 不要把研究岗的论文要求当成所有 AI 岗位的门槛；逐条检查专业和学历 |
| 本科/硕士，有视觉或嵌入式项目 | 图像算法、机器视觉、图像处理、SLAM、感知、算法部署、边缘 AI | 工业、医疗、机器人、汽车方向常需要领域知识；部分岗位仅招硕士 |
| 硕士，有机器学习项目 | 推荐/搜索/风控、时序预测、运筹优化、NLP、多模态、数据挖掘 | 区分业务算法、算法工程和研究科学家，不要只搜“大模型” |
| 博士或科研成果较强 | 全职研究员、科学家、博士专项 | 检查论文方向、毕业时间、正式聘用与合同类型 |
| 已毕业未就业 | 明确接收本人毕业届别的校招、无经验要求的初级岗、项目聘用岗 | **不要默认“2027 校招”接受 2026 届**；以各单位资格条款为准 |

- 数据与决策：`数据挖掘`、`推荐`、`搜索`、`风控`、`运筹`、`优化`、`时序预测`。

## 十七、给老师的分发与跟进建议

### 1. 每人先建立三组投递池

- **专业匹配组**：项目、课程、论文与职责明显匹配的岗位。
- **工程扩展组**：AI 应用开发、部署、数据工程、测试开发、行业软件等能用现有能力举证的岗位。
- **行业扩展组**：从医疗、制造、能源、物流机器人、金融科技、遥感等选择与个人背景相关的岗位。

不要把“扩大渠道”变成向无关岗位海投。每个职位先核对以下五项：

1. 是否接受本人毕业时间/届别。
2. 是否满足学历、专业和经验硬条件。
3. 职责能否用现有项目、课程设计或过往经历举证。
4. 是否为正式全职工作，工作城市和入职时间是否可接受。
5. 是否仍在收简历，以及投递入口是否来自官方。

### 2. 简历至少按方向调整

- **开发版**：突出完整应用、接口、数据库、测试、部署及故障排查；AI 应用写清 RAG/Agent 是否实际运行及如何评估。
- **算法版**：写清任务、数据来源、基线、指标、误差分析和自己的贡献，避免只列模型名称。
- **行业版**：围绕视觉缺陷检测、负荷预测、路径优化、医学影像等具体任务描述经历，不虚构行业经验。

### 3. 投递跟进表模板

| 学生 | 单位/团队 | 岗位名称/编号 | 招聘类型 | 届别与学历已核对 | 城市 | 实际投递链接 | 投递日期 | 状态 | 下次动作 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
|  |  |  | 秋招/校招补录/春招/初级全职社招 | 是/否 |  |  |  | 未投/已投/笔试/面试/结束 |  |

### 4. 几个容易浪费投递机会的地方

- 同一集团可能限制投递岗位数或志愿顺序，先看规则再投。
- 有些岗位名称是“软件工程师”，职责才写大模型、智能体或图像处理，不能只用“算法”搜索。
- 有些“AI 岗位”实际是销售、标注、课程培训或交付支持，按职责判断，不把它们混为研发岗位。
- 本清单只用于正式工作。排除 Internship、实习生、研究实习、转正实习；也不要把人才培养项目或课程培训当成正式录用。
- 不向招聘方支付培训费、内推费、保 offer 费；不要向无法核实身份的人提交身份证、银行卡等敏感信息。

## 十八、核验口径与局限

- 表内优先提供公司/机构自有域名、官方招聘域名，或明确标注的第三方招聘平台。
- **招聘系统入口**与**官网导航入口**分开标记。后者需要从官网找到“加入我们/人才招聘”，不是一键投递链接。
- 对使用动态加载、登录、验证码、地区跳转的站点，技术连通性不能证明存在有效空缺。
- 本次实际访问了公开官网和招聘页面，读取标题、招聘导航及可见正文；未登录招聘账户，也未替学生提交申请。正文可读的招聘信息已放在开头，其他仅核对入口或保留待核实线索。
- 岗位方向是辅助检索词，不能替代招聘 JD；本文不编造发布日期、薪资、HC、学历下限、城市或截止时间。
- 以 2026 年 11 月 3 日为整理时间。之后使用应重新打开链接检查，尤其不要从旧公告推断当年仍在招。
- 这份清单适合先建立投递池。若要精确筛到“今天仍可投、接受指定届别/学历/城市”的职位，需要针对学生条件逐岗核对。
